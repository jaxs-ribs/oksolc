# OKcontract response to Hackerbane audit HB-AR-2026.17

Prepared for Hackerbane by the OKcontract team on October 2, 2026; updated October 3, 2026.

We reviewed all 29 findings in [HB-AR-2026.17](hb-ar-2026.17-oksolc.html). This branch fixes 21 findings and partially fixes HACK-19 with a deliberate IR spelling exception. HACK-14 was already fixed on main. HACK-05, HACK-15, and HACK-17 are intentional compatibility differences, HACK-26 describes an intentional feature boundary, and HACK-27 and HACK-29 concern upstream behavior.

The table distinguishes fixes required for correctness or existing policy from recommended compatibility refinements. The proposed HACK-05, HACK-15, and HACK-17 changes are declined: they reproduce upstream quirks or add unnecessary compiler work. Each fix was kept minimal, reviewed before committing, and written for Zig 0.16.0.

**HACK-28 was independently discovered by the OKcontract team on August 21, 2026.** We accept the finding and deliberately correct it in oksolc. For `error X(uint256 a, uint256 b)`, `require(false, X({b: 2, a: 1}))` reverts with `X(1, 2)`. The same example produces `X(2, 1)` in solc 0.8.36 via-IR.

The fix passes values to the custom-error helper in declaration order after evaluating the expressions in their existing order. Arguments still evaluate when the condition is true. The [named-error fixture](../test/zig/standard-json/solidity-require-named-errors-bytecode.json) covers the OKcontract literal example, runtime values, mixed types, calldata strings with multiple stack slots, and side effects. A [positional-call solc reference](../test/zig/standard-json/solidity-require-positional-errors-bytecode.json) supplies the expected bytecode; local EVM checks also verify the actual revert payloads and unchanged named-event and direct-revert behavior. This is a documented correctness exception to byte compatibility with solc 0.8.36.

For HACK-05, we retain rejection of incomplete hexadecimal subassembly indices such as `0x`, `0X`, and `0xg`. Treating these as index zero reproduces a C++ parsing quirk without a correctness benefit. Valid prefixed indices remain supported.

For HACK-15 and HACK-29, we retain the original `reserved_memory < 2^32 - 1` guard. We decline the lower `2^31` ceiling caused by upstream shift precedence. The separate slot-count bound and checked memory-offset arithmetic remain enforced.

For HACK-17, we decline the proposed fix. Generating unused helpers solely to match solc unoptimized IR adds compiler allocations and optimizer work without a correctness benefit. Helper generation is conditional and retains its ownership and cleanup rules. The reduced empty-contract case matches solc optimized IR and bytecode. The HACK-23 explicit-IR reference omits only unused deployed-object helpers; creation helpers and optimized IR remain exact.

For HACK-19, array bounds use the readable hexadecimal spelling `0x10000000000000000` for 2^64. Custom-error selectors use hexadecimal spelling, and byte-array pop helpers follow solc ordering. Selector literals retain their numeric value directly and format their spelling from fixed-size stack data into one allocation owned by the output arena, without temporary heap buffers or reparsing. Only the equivalent bound spelling differs from solc in those IR fixtures; bytecode remains exact.

The reference compiler was `solc 0.8.36 --standard-json`. Standard JSON comparisons are exact except unoptimized IR, which uses the repository’s Yul-token comparator. The named-`require` reference uses equivalent positional calls with CBOR metadata disabled; side effects are evaluated in source order before those calls.

Validation on Zig 0.16.0 passed:

- Full Debug unit suite with browser support enabled and debug symbols stripped: 50/50 build steps, 1,033/1,033 tests.
- ReleaseFast CLI and C ABI smoke tests, frozen solc compatibility, formatting, and lint: 105/105 build steps, 5/5 corpus tests; lint reports no issues.
- Two direct policy tests: incomplete hexadecimal subassembly prefixes are rejected; `memoryguard` accepts `2^31` and `2^32 - 2` and rejects values at or above `2^32 - 1`.
- Eleven local Anvil 1.7.1 EVM checks using freshly compiled HACK-28 fixtures: correct revert payloads, eager argument evaluation, source evaluation order, named events, direct revert, and reproduction of the solc 0.8.36 defect.
- A direct empty-contract comparison with solc 0.8.36 confirms identical optimized IR and bytecode while omitting the unused selector helper from unoptimized IR.

The supplied HTML is preserved unchanged. The report references external audit vectors that were not supplied, so this response does not claim a rerun of the full original Solady, OpenZeppelin, or Seaport workloads. No response or upstream issue report has been sent externally.
