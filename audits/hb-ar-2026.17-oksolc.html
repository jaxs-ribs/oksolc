1   Executive overview

1.1   Introduction

oksolc 0.1.4 compiles Solidity through the via-IR pipeline and aims to match solc 0.8.36 bytecode. Hackerbane reviewed okcontract/oksolc at commit a59339132a1aecc8594a34cbba6b5a1bffbeeca8. The oracle is solc 0.8.36+commit.8a079791, source tag v0.8.36 commit 8a079791d9cca7a6c03fd6a8429b93aa3bddefed. Report date is 30 September 2026. Scope is in section 2.4.

1.2   What we found

Creation and runtime bytecode matched solc on the 50-source via-IR campaign and on the frozen corpus (5/5). Seaport 1.6 matched, including the one stack-too-deep error. That is the path the README supports.

HACK-01 is assembly JSON import. parseAssemblyJSONNode applies .data strings in parse order. solc applies them in sorted key order. Two keys for one hash, differing only by case, deploy 22 on oksolc and 11 on solc. oksolc does not ship an import-asm-json command. Its JSON printer sorts keys, so a round trip of an oksolc export does not hit HACK-01.

Fifteen High findings are open. HACK-02 follows a symlink out of the project on oksolc compile. HACK-03 through HACK-05 are the other assembly JSON integer parsers. HACK-06 aborts on super.f() when the next base is unimplemented. HACK-07 through HACK-13 accept Solidity that solc 0.8.36 rejects, or drop an overload solc compiles. HACK-14 aborts on using L for * when a zero-argument overload exists (Solady 0.1.26, reduced). HACK-15 emits bytecode for memoryguard at 2^31, where solc hits an internal compiler error. HACK-16 dies in the unused pruner on OpenZeppelin 5.6.1, reduced to ERC721ConsecutiveTarget plus 37 imports.

Three Medium findings are IR text that differs while Solidity bytecode matches. Six Low findings are diagnostic codes, JSON field shape, or a Yul literal that both compilers reject under different error classes. Four Informational rows cover viaIR: false and three solc behaviors: named require field order, the memoryguard shift precedence, and a SIGSEGV on assembly tag 2^32-1 (HACK-27).

1.3   How this review was done

  • Line read of the via-IR pipeline, Yul optimizer, EVM assembly, Standard JSON, paths, and the incremental cache, recorded in audit/04-review/.
  • Differential compile of 50 Solidity sources, via-IR, optimizer runs 200, cancun, against solc 0.8.36. Creation and runtime bytecode matched. A second batch covered try/catch, modifiers, immutables, and Yul loops.
  • Issue 8 inputs: Seaport 1.6 (bytecode match, shared stack-too-deep), Solady 0.1.26 (HACK-14), OpenZeppelin 5.6.1 (HACK-16).
  • --jobs 1 and 4 matched a serial compile. A user-config SQLite cache matched --no-cache on that input.
  • EMI on two contracts with metadata stripped. Opt-level matrix: optimizer off, runs 1, 200, and 1000000, shanghai and cancun. Bytecode matched.
  • 63 bugs.json shapes, plus 18 blog proofs of concept that had a static code block, and the SOL-2023-3 Yul verbatim object. No bytecode diff.
  • Assembly JSON import harness: Assembly.fromJSON then assemble, compared with solc --experimental --import-asm-json --bin. The harness source was removed after the run.
  • zig build lint reported no issues. zig build fuzz-json-adapter under ASan passed 1000 mutations plus 5 seeds. Two unit-test binaries that the build log marked failed command were re-run and passed 141 and 583 tests.

Each finding gets a BVSS vector. Exploitability is Attack Origin, Attack Cost, and Attack Complexity. Impact is Confidentiality, Integrity, Availability, Deposit, and Yield. The coefficient is Reversibility times Scope. The printed score is min(10, E * I * C * 10), rounded up to one decimal.

S = min(10, E * I * C * 10)
